# SeaWorld Lab Sheet Intake — Phase 1

This folder set is a front-end proof of concept for `cmiller-lab/calc-and-report-beta`.

## What is included

- `lab-sheets.html` — technician-facing submission history.
- `lab-upload.html` — minimal iPad camera/upload test page.
- `lab-config.js` — non-secret environment/configuration values.
- `lab-api.js` — front-end API adapter.
- `service-worker.js` — updated cache list that includes the new Phase 1 pages.
- `README.md` — updated project overview.

Phase 1 intentionally runs with `demoMode: true`. No customer photograph is transmitted or stored until a secure backend is configured.

## Security boundary

Do **not** put any Supabase service-role key, database password, private storage credential, or reusable technician credential in browser JavaScript.

The browser/PWA should only call limited-purpose server-side endpoints. The customer iPad/Shortcut should receive a dedicated device credential that can upload lab sheets but cannot browse storage, query arbitrary tables, or perform administrative actions.

The original photograph should remain the authoritative source record. OCR/extracted values added later should reference the original submission and should never overwrite it.

## Proposed Supabase backend

### Storage

Create a **private** bucket named:

`lab-sheets-originals`

Suggested object layout:

`seaworld/YYYY/MM/DD/<submission-uuid>/original.jpg`

Do not make the bucket public. Technician viewing should use short-lived signed URLs generated by a trusted server-side function.

### Table: `lab_sheet_submissions`

Recommended fields:

| Field | Type | Purpose |
|---|---|---|
| `id` | uuid primary key | Submission identifier |
| `site_id` | text | `seaworld` |
| `submitted_at` | timestamptz | Server receipt time |
| `captured_at` | timestamptz nullable | Device/photo capture time if available |
| `device_id` | text | Stable authorized device identifier |
| `device_label` | text | Human-readable device name |
| `storage_path` | text | Private original image object path |
| `original_filename` | text nullable | Original client filename |
| `mime_type` | text | e.g. `image/jpeg` |
| `file_size_bytes` | bigint | Upload size |
| `status` | text | `received`, `processing`, `ready`, `review`, `failed` |
| `round_label` | text nullable | e.g. `10:00 AM Round` |
| `processing_error` | text nullable | Safe processing failure detail |
| `created_at` | timestamptz | Record creation time |
| `updated_at` | timestamptz | Last state change |

Future OCR tables should be separate from the submission record so the original source remains immutable.

### Edge Functions

Use three limited-purpose functions:

1. `lab-sheet-upload`
   - Accept `multipart/form-data`.
   - Authenticate a dedicated device token.
   - Resolve `site_id` and `device_id` server-side from the token.
   - Validate MIME type and file size.
   - Generate the UUID/storage path server-side.
   - Upload to the private bucket.
   - Insert the database row.
   - Return only the new submission ID and safe status metadata.

2. `lab-sheet-list`
   - Used by the technician PWA.
   - Return recent records for authorized technician users.
   - Do not return storage credentials.
   - Optionally include a short-lived signed photo URL.

3. `lab-sheet-image`
   - Alternative to returning signed URLs in the list call.
   - Validate technician authorization.
   - Generate and return a short-lived signed URL for one submission.

## Device-token model

Use a server-side table such as `lab_sheet_devices` containing a hashed token, device ID, site ID, enabled flag, and last-used timestamp. The raw token should exist only on the dedicated iPad/Shortcut and should never be committed to GitHub.

A device token should only grant permission to submit for its assigned site. It should not allow listing records or reading photographs.

## iPad Shortcut target workflow

Once `lab-sheet-upload` exists:

1. Take Photo.
2. Get Contents of URL.
3. Method: POST.
4. Request Body: Form.
5. Add the image as `photo`.
6. Send the device token in the header expected by the Edge Function.
7. Treat only a confirmed HTTP success response as submitted.
8. Show a large success message; otherwise show an obvious failure message.

Optional reliability improvement: save the photo to a local/iCloud recovery album before uploading.

## Connecting the Phase 1 pages

After the backend exists:

1. Change `demoMode` in `lab-config.js` to `false`.
2. Set `apiBaseUrl` to the deployed Edge Function base URL.
3. Keep all privileged credentials server-side.
4. Validate upload and list calls on cellular and SeaWorld Wi-Fi.
5. Test service-worker updates on an already-installed PWA.

## Recommended next phase

After upload → storage → technician viewing is proven reliable:

- expected-round/overdue logic,
- push/SMS/email notifications,
- image deskew/crop,
- fixed-region handwriting extraction,
- confidence scoring and technician correction,
- controller snapshot at lab-round time,
- lab-vs-controller deltas,
- per-pool calibration and ORP/free-chlorine trends.
